# SEU-Pulse 第一阶段项目报告

SEU-Pulse 支持网页直接采集与已有 RSSHub 两种方式并用，共享通知模型、SQLite、Python 服务接口与 CLI。获准沙箱外联网后，教务处国际交流和吴健雄学院通知公告均通过真实采集验收：各入库 14 条，共 28 条，其中 12 条取得文本正文；第二轮新增 0、未变 28。查询、正文及身份稳定性验证通过，36 项离线测试通过，已有实现和数据库保留。

报告面向项目维护者和后续 Agent 接入方，依据当前 [AGENTS.md](../AGENTS.md)、[require.md](../require.md)、[agent.md](../agent.md) 和 [tasks.md](../tasks.md)。本轮未修改需求、接口契约或执行规则。安装、运行及来源复验命令集中维护于 [README](../README.md)。

## 架构与接口

数据流为 TOML 配置 → 服务选择来源 → 采集适配器 → 统一模型转换 → SQLite 事务 → 服务查询或 CLI 导出。未来调用方只需要 `PulseService`，不需要依赖采集器或 SQL。

`models.py` 管理通知模型、UTC 时间、身份及内容指纹；`collectors.py` 负责公开网络请求与原有 RSS/HTML 转换；新增 `webpages.py` 负责列表及正文直采；`storage.py` 管理来源、通知与运行记录；`service.py` 组织来源隔离和查询；`cli.py` 提供命令入口。新架构复用现有 urllib 和 HTMLParser 等效实现，未增加重复 HTTPX/BeautifulSoup 网络栈或浏览器依赖。

原有来源 ID、SQLite 表和服务签名保持兼容，切换采集方式不需要重建数据库。纯网页配置可省略 RSSHub 地址；旧 RSSHub 配置仍可加载。正文失败不会丢弃列表记录或清空已有正文，最新原因保存在 metadata 中；正文恢复后会清除旧错误。来源成功计数仅代表列表采集完成，正文是否成功须独立检查。

通知严格使用 v1 的 13 个字段。无法确定时区的发布时间保持 `null`，原日期存入 metadata；首次发现和最近采集时间均使用 UTC。身份不含正文或采集时间，内容变化不改变 ID。内容指纹排除采集时间和来源元数据，缺失摘要、正文等字段不会清空已有值。

错误分为来源错误和服务错误。来源请求、解析或模型转换失败写入逐源结果，其他来源继续；参数、配置与服务级存储失败显式抛出。来源转化完成后才开始写入，避免半批解析成功造成部分入库。存储故障回滚当前来源，已提交的其他来源保留。

## 来源核查与选择

教务处国际交流与吴健雄学院通知公告现为重点来源，默认启用网页直采。用户服务器返回的两个 HTTP 200 只作为连通性证据，不作为正文解析成功或本执行环境可访问的依据。具体地址、样本链接及验证状态集中见 [README 来源核查表](../README.md#来源核查表)。

现已直接保存两站原始列表和每站两篇可读文本正文，确认正文使用 wp_articlecontent/Article_Content。教务处页面页头轮播原先会混入其他栏目，已依据真实 HTML 将列表范围限定为 wp_news_w8；吴院限定为 col_news_list，并增加范围匹配回归测试。每站当前解析 14 条本站列表记录，均有标题、链接及原始日期。

原始样本包含受限重定向、微信公众号及纯 PDF 条目，采样器在最多六篇本站文章中找到两篇可读正文，保留所有检查结果与原因。无法确定日期时区时仍保持 published_at=null，原始日期存在 metadata；未把网址中的日期当作发布时间。

前轮已从 RSSHub 官方源码核对计算机学院 `/seu/cse/tzgg`、研招网 `/seu/yzb/6676` 和信息学院 `/seu/radio/academic`。现在这三个来源默认关闭，按需启用，不阻塞重点来源；官方文档和路由注册表复核暂缓。

研究生院“全部公告”的旧版静态列表适配器继续保留并默认关闭。未删除旧源码、测试、配置来源或历史验证记录。

已见样本未提供必须执行 JavaScript 的证据，因此不启用 Crawl4AI 或 Playwright，也不为本执行环境的网络限制建立代理、远程接入或部署设施。预留的浏览器可选依赖继续保留，基础采集不导入它。

## 测试和安装证据

环境为 Python 3.10.12。本轮复用前轮实现，原 29 项测试全部保留；新增网页列表和正文、访问限制、正文失败及恢复、混合采集、纯网页配置与旧配置兼容性测试。`.git` 仍为空，`git status` 报告不是有效 Git 仓库；未初始化或修改 Git 元数据。

离线测试使用明确标识的 RSS、Atom 和 WebPlus fixture，覆盖以下行为：

- 带时区与无时区日期解析、UTC 转换、通知字段及 JSON object 元数据约束。
- URL 规范化、GUID 和标题降级身份、身份与内容指纹分离。
- SQLite 首次写入、重复去重、内容更新、缺失字段保留、重开读写、唯一约束及事务回滚。
- RSS/Atom 映射、静态列表解析、有效空订阅与错误页面区分。
- robots、超时、请求间隔、有限重试、响应大小、访问限制及错误摘要脱敏。
- 单源失败隔离、持久化采集间隔、参数错误、空正文与不存在记录区分、存储错误传播。
- CLI 查询、退出码、运行状态及 v1 JSON 导出。
- 实际适配器、解析器、服务和 SQLite 的组合闭环：首次写入 3 条，重复采集 0 条新增且 3 条未变，正文变化后 1 条更新、2 条未变。
- 网页与 RSSHub 在同一轮各成功处理 3 条测试通知，共 6 条；重复新增 0 条。网页来源故障时 RSSHub 继续成功，原记录保留；正文失败保留已有正文，恢复后更新内容并清除错误。

最终 36 项测试在开发环境和独立安装环境均通过；详情见 [tasks.md 的最终结果](../tasks.md#获准联网后的最终结果)。离线测试不访问外网，真实采集另有独立证据。

Python 包已构建为 `seu_pulse-0.1.0-py3-none-any.whl`，在独立虚拟环境安装后，入口 `seu-pulse --help` 正常，`pip check` 返回 `No broken requirements found.`。由于包索引网络受限，验证时在临时目录复用系统 pip 自带的 tomli 1.0.3 构建本地依赖 wheel；项目运行时代码只导入标准 tomli/tomllib，不依赖 pip 私有 API。未宣称本环境已验证从外部索引下载依赖。
