## 3. 通知与事项分类及优先级层级

- notice_category.primary为整条通知的主要类别，至多一个；secondary为有证据的辅助通知类别，topic_tags为细主题，不混入matter_type。主分类与辅助分类分别评价。
- matter_type描述具体业务事件，如申请/审核/缴费/公示/活动/结果发布；matter_subject保存责任/参与主体，matter_purpose说明目标，time_nodes按具体事项、步骤或选项归属。
- 推送资格、个性化重要性在通知层；时间节点、过期状态和紧急程度在事项层。通知整体紧急程度如何汇总、哪些主体Deadline触发软件消息均待确认，不默认最大/最近截止，不默认所有审核都提醒学生。
- 15条没有真实用户偏好，个性化重要性不可评；展示资格政策未定，推送资格也不可评。null不等于普通或不推送，也不作为这些维度的正确答案计分。
- 已确定非常紧急为未过期且剩余不超过24小时；较紧急上界、正好截止时刻仍待确认，不沿用72小时。过期/无截止/未知截止独立表达，不发消息、不创建待办。

## 4. 事项匹配与评估口径（建议，尚不执行）

### 4.1 先做有约束的等价规范化

1. 参考先固定独立事项身份与必要组件、可接受合并/拆分、主体职责及目标场景，再匹配；不能先看预测结果改变分母。本15条仍是探索性来源核对，不宣称完整Benchmark或盲测。
2. 在同一notice_id内，以业务对象/目标、流程场景、责任角色和时间上下文对齐，不要求名称逐字相同，不用相同日期作为唯一匹配键。字段值不必全对才允许对齐，否则会把字段错误藏进“未匹配”。错绑到另一个业务目标则不能视为同一事项。
3. 第3条两场复试合并或分列均可映射到同一“复试考核”参考身份；场次组件必须保留英语/综合素质，候考不可合并成面试开始。分列两场不比完整合并多得一个独立事项TP，缺一场的内容漏失另在必要组件/字段覆盖中体现。
4. 第9条一个项目+五个选项，与显式标明option_of/五选一的嵌套或展开结构等价；五个互不关联的活动、或宣称学生全部参加不等价。第10条9场按学科/重复场次/日期原文区分，首场导语与9月29日同场合并，不多计。
5. 出国审核可用联合审批父容器表达，但学院与国际合作处责任须各有可识别组件，规范化后对应本稿各一条责任事项；不得据此推定审核先后。不同学生申请、学院审核、缴费、外方网申、KTH/校级奖学金、公示/结果不能因同日、同项目或放进一个父容器就被消掉。
6. 操作步骤、资格/费用/预期成果、选项、背景不进入独立事项分母；分别检查信息保留和层级正确性。可单列成果对象但明确关联为expected_outcome时等价；把“可能获推荐信”断言成已获得或新的无依据流程不能在评分时替模型纠正。
7. 规范化后按独立身份做一对一匹配；一个身份最多记一次TP。重复的独立预测在去除允许的表示差异后仍多余，则记FP；不能靠重复条目抬高召回。剩余参考为FN，剩余预测为FP。必要组件、字段与非独立信息的遗漏单列，不能以识别出父事项掩盖内容不全。

### 4.2 分开报告指标，不合成action accuracy

| 指标 | 建议定义与分母 | 必须附带的计数/限制 |
| --- | --- | --- |
| 独立事项Precision | TP / (TP + FP)；TP为经等价规范化后一对一命中的独立身份 | 显示TP/FP；纯步骤、属性、选项不因被保留而增加TP；假造独立流程可构成FP |
| 独立事项Recall | TP / (TP + FN) | 显示FN及漏项；另报必要组件/非独立信息覆盖，父事项命中不等于所有内容正确 |
| 独立事项F1 | 2TP / (2TP + FP + FN) | 建议同时给微观汇总和逐通知结果；不以显示条目数代替规范化单位 |
| 关键字段准确率 | 正确且有依据的可判定参考字段数 / 全部可判定参考字段数；漏事项/漏字段在端到端口径计错 | 名称/类型/对象/条件/费用/要求/成果/未知与冲突状态分别列；不只统计已命中的字段 |
| 时间节点提取准确率 | 建议用节点集合准确率（Jaccard口径）：TP_time / (TP_time + FP_time + FN_time) | 这是集合提取口径，不是有真负的分类accuracy；另列时间P/R和漏提/多提/错绑数，分母待最终确认 |
| 主体与目的识别准确率 | 分别给正确主体数/可判定参考事项数、正确目的数/同分母，以及两者均正确的比例 | 漏事项计错；主体不明时评保留未知的行为，不编造执行机构；不只在全对匹配结果上统计 |
| 无依据提取率 | 无原文支持或把来源不确定性升级为确定事实的唯一断言数 / 全部唯一事实断言数 | 按独立事项、字段、时间分型；重复事实先规范化，不能用重复正确字段稀释；有原文但归错层与凭空编造分别列 |

时间节点身份包含owner_ref（事项/步骤/选项）、主体目的、start/end/deadline/relative角色及场景。完整正确节点需原文、可支持的归一化部分、未知/冲突处理及归属均正确。同日网申与奖学金是两个目标；冲突日期属于一个节点的两个候选，不能当两个独立截止。原文13.00保留、规范化未知是正确表达，不因没有冒号格式而扣原文提取分。相对“1—2工作日”“考核后4周”保留关系，不补日历日期。

对于日期/时刻/时区、原文和归属还应分别报告字段结果，避免整个节点全错掩盖正确部分；没有可判定时间节点时指标为不可评，不默认为满分。背景历史日期与选项/步骤节点仍进入各自的信息/时间覆盖清单，但不抬高独立事项Recall。

零分母报告N/A并列原始计数，不写100%。有可观察参考事项而模型完全失败/无输出时，端到端FN覆盖全部参考，Recall/F1为0；无独立预测的Precision为N/A，并另列技术失败。正文不可用的第2/6/7条只评标题能支持的已知参考，未观察到的真实细节不假造为FN。推送资格/个性化重要性不可评维度不进入分母。旧v1输出本轮不投射成新结构计分。

### 4.3 其他维度继续独立

通知主分类正确性与辅助类别/标签分开；非独立资料保留率、时间精度/冲突保留、层级正确性、程序紧急计算、工具必要性/执行反馈/证据遵循均单列。确认匹配单位和字段清单后才可建立真实分母；不得混成一个总分或把工具成功当语义正确。合成偏好另设计、另报告，不代表这15条的真实个性化能力。
